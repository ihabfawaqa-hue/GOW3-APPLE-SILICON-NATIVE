# Engineering decisions

Updated: 2026-10-24.

| Decision | Rationale | Status |
|---|---|---|
| Preserve the existing native ARM64 CPU/runtime. | The current binary runs natively on Apple Silicon and reaches the opening sequence. | Active |
| Make the GoW3-adapted shadPS4 video core the target production GPU owner. | Exact candidate commit `b907d8a9f2324ba5f514fbfe7de803e027c6ca26`, shadPS4 base `b4e7ae776071ceb1dd35004577a8719481e1d258`; three required game-specific regressions pass, and full standalone CMake target builds arm64. Candidate commit `71d70a6` now passes KosmicKrisp presenter initialization and GNM registration in isolation. | Approved; runtime ABI/memory integration and teardown pending |
| Keep custom Metal as a diagnostic comparison backend. | The default run reproduces the post-splash corruption. Enabling its optional GCN-to-MSL path produced mostly black frames and logged MSAA texture translation fallbacks for three shader pairs. This path is useful for diagnostics but is not a correctness oracle or the production backend. | Active |
| Gate active Metal EOP visibility on actual command-buffer completion. | The previous parser wrote guest EOP labels and posted the GNM event while only decoding PM4. The revised path ends active encoders, commits and waits for the preceding Metal command buffer, then performs checked release stores and raises only the requested interrupt. It implements the GPU-clock and performance-counter EOP data selections; `sceGnmGetGpuCoreClockFrequency` now returns the selected 800/911 MHz clock in hertz, matching the pinned source. Unsupported GDS stores are explicit and rate-limited. A bounded PS4 Pro run sampled 6,240 completed EOP operations without rejections, but the captured post-splash frame remains a black/white split. This is a correctness guard for the current comparison backend, not a promotion of Metal or proof of the candidate Vulkan contract. | Implemented and bounded-run verified |
| Do not route through the existing `gow3gpu_bridge.cpp` as-is. | It is a placeholder with fabricated NIDs, no runtime callers, an in-memory map that does not own guest memory, and forwarding back to Metal. | Active |
| Keep the vendored shadPS4 shader recompiler separate from the full GPU backend. | Its GCN-to-SPIR-V frontend can be useful, but its current MSL integration cannot replace the Vulkan GPU resource and synchronization layers. | Active |
| Keep the optional `GOW3_GCN=1` GCN-to-MSL path diagnostic-only. | A bounded run translated its latest 512 draw events but produced black output with a large yellow polygon; three actual fragment shader pairs still fall back on multisampled textures. The translator's Metal texture path accepts only Color2D and does not reproduce full GPU resource/cache semantics. | Tested; not promoted |
| Validate captured shaders with the pinned renderer's SPIR-V profile and exact capture inputs. | The probe consumes captured flat-user-data reads and their guest memory values, preserves resolved-resource provenance, emits SPIR-V 1.6, runs `spirv-val --target-env vulkan1.3`, and compiles cross-compiled MSL to Metal AIR. The latest VS/PS and all three guest VS buffers pass. This is frontend evidence only, not Vulkan pipeline or game output evidence. | Implemented; one captured shader pair passes |
| Validate DCB, index, vertex descriptors, and shader dependencies before blaming vertex fetch. | The bounded capture now saves the pinned translator's five resolved V# inputs and three complete VS guest buffers, with manifest hashes. The diagnostic Metal replay binds those exact resources, the captured index stream, viewport/scissor and decoded base vertex. Two runs have identical readbacks, but render only 158 pixels with no known-good reference; guest depth, blend, textures and the rest of the pass are absent. | Implemented for one complete-input diagnostic draw; full render-pass replay pending |
| Test KosmicKrisp first and MoltenVK independently. | The source-based probe finds sparse buffer features unavailable on both M2 drivers; MoltenVK also lacks robustness2/nullDescriptor. Both pass a separate BDA page-table primitive that writes through two independent resident buffers and verifies host readback. This supports a sparse-free cache investigation but does not cover contiguous direct descriptors, alias coherence, or guest-memory synchronization. | Primitive PASS; pinned renderer still FAIL |
| Keep the imported GPU candidate isolated until it passes a real workload. | The candidate now installs typed memory/host callbacks, routes live submit/done imports, and reaches shader compilation; a guest fetch shader is read through the callback. The BDA probe validates one possible primitive for non-sparse ranges, but the cache still depends on sparse 1–4 GiB arenas and the guest workload fails before draw execution. | Keep it opt-in and isolated; do not promote until range bindings, aliasing, completion, VideoOut, and lifecycle gates pass |
| Route candidate guest submissions only through explicit adapters. | The isolated runtime-integration branch now uses a typed, opt-in loader and submit/submit-done adapters; a real guest workload reaches the pinned shader compiler. Keep this behind `PS4_GOW3GPU_BACKEND=gow3gpu-vulkan` until Vulkan sparse-memory compatibility, GPU completion, and integrated VideoOut are demonstrated. | Candidate import route PARTIAL; not promoted |
| Keep guest memory access explicit and short-lived through checked leases. | Candidate callbacks use checked leases and process-VM allocation. Synthetic lease/atomic/writeback tests pass, and the opt-in game run successfully copies a guest fetch shader through the installed API. Protected-page faults, GPU-write visibility, EOP and equeue synchronization remain unverified because renderer setup fails at sparse buffers. | Candidate guest read tested live; full memory synchronization pending |
| Dispatch imported GPU page faults before generic fatal signal reporting. | The runtime atomically loads an optional handler and offers SIGSEGV/SIGBUS to it before dumping a crash. A synthetic callback test verifies handled/unhandled dispatch and callback removal; the opt-in loader installs the hook, but the current sparse-feature gate stops before a protected guest page can fault. macOS uses 16 KiB host pages while the candidate tracker operates at its configured guest-memory granularity. | Dispatch seam and installation tested; live protected-page behavior pending |
| Keep video decoding in the existing ARM64 HLE and copy guest buffers through checked memory APIs. | Candidate branch integrates the checked decoder from commit `51bc033`. `python3 tests/test_videodec_h264.py` passes; run `run_20261024_061251_539768` reaches QueryResourceInfo, H.264 creation, and one decoded 1920×1088 frame without an unimplemented shim. This adds Homebrew ARM64 FFmpeg libraries to `ps4_app`; decoded-to-presented cinematic correctness remains open. | Implemented; game frame decode observed, presentation unverified |
| Use the smallest local macOS Vulkan portability fix. | The unpatched source cannot create a MoltenVK instance because it omits portability enumeration and device subset enablement. The isolated patch only adds those loader/device requirements; it does not remove required renderer features. | Committed with the native port at isolated branch `342f841`; build passed |
| Keep Cocoa window and event ownership on the macOS main thread. | Standalone initialization first failed because SDL had no Cocoa video device, then because the window was created from a worker. The isolated patch creates the SDL window and `CAMetalLayer` on the main thread and polls events from a main-queue timer; KosmicKrisp presenter initialization now passes. SDL documents `SDL_Metal_CreateView` as main-thread-only. | Implemented and isolated-init tested; runtime event-loop integration and shutdown remain pending |
| Keep local game inputs and captures out of version control. | The user supplied paths contain proprietary assets and derived guest code. | Active; enforced by `.gitignore` |

## Ownership target

| Subsystem | Owner after integration |
|---|---|
| Recompiled CPU, HLE, guest address-space mapping | Existing ARM64 runtime |
| GNM imports, PM4, shader compilation, texture/image cache, render state | Imported GoW3/shadPS4 GPU |
| GPU completion and interrupts | One explicit bridge contract with the existing equeue/thread runtime |
| Page tracking | Shared guest-memory API; runtime owns mappings, GPU cache subscribes to invalidations |
| Presentation | Integrated VideoOut path with one renderer owning each presented frame |
| Custom Metal renderer | Diagnostic/differential backend only |

Each shared contract still needs concrete API and synchronization tests before integration.
