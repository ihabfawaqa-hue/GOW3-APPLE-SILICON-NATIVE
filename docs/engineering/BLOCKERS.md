# Verified blockers

Updated: 2026-10-24. Evidence below separates capability failures from missing integration work.

| Severity | Blocker | Evidence | Next falsifiable action |
|---|---|---|---|
| Critical | Production GNM/VideoOut still use custom Metal. | The primary call graph routes `sceGnmSubmitCommandBuffers` to `ps4_gnm_metal_process_command_buffers`; no live caller reaches imported `gow3gpu_init` or Liverpool PM4. Latest run `run_20261024_043735_477572` confirms native Metal: both splash cards match verified image hashes, then a black/white split at sample 900 repeats through sample 1350. The current Metal backend waits for actual Metal command-buffer completion before publishing EOP labels/events, and the PS4 Pro run records 6,240 sampled EOP completions without rejected/withheld events. The `GOW3_GCN=1` experiment remains native Metal and repeatedly falls back for shader pairs `0xbdded400/0xbdded000`, `0xfb645400/0xfb645000`, and `0xbbe04400/0xbbe04000` because fragment MSAA textures are not translated. Candidate commit `a0a7a9d` proves a synthetic `GuestContext` NOP can reach the real candidate HLE/Liverpool queue, but it is isolated; no game import reaches it. | Complete the candidate-specific import, memory, completion and VideoOut contracts, then route one bounded real submission with one presentation owner. |
| Critical | The candidate guest-memory API is not connected to the primary runtime. | Primary CPU leases validate full ranges and permissions under direct-memory-then-VM locks. A separate primary GPU lease/read/write API now validates allocated guest extents while allowing GPU access through CPU-PROT_NONE ranges; a synthetic test covers this and rejects free extents. The isolated runtime-integration candidate at `/Users/ihabfawaqa/Downloads/gow3-arm64-runtime-int`, commit `36e89bf`, has a v1 callback surface and synthetic arm64 tests for sparse reads, write-back, reverse host mapping, atomics, protection and mapping hooks. The primary runtime has not installed those callbacks or connected page-fault and GPU-write invalidation ownership. | Implement and test the primary-runtime callback adapter against mapped, sparse, read-only and concurrent guest ranges; then exercise page-fault invalidation and GPU write-back before routing a submission. |
| Critical | GPU page protection and fault ownership are not integrated into the production runtime. | Primary `recomp_vm_set_protection` only changes logical guest metadata; its host mappings remain RW. Candidate commit `36e89bf` aligns the imported tracker to Apple arm64 16 KiB host pages and passes synthetic protection and mapping-hook tests, but the candidate adapter is not installed by `ps4_app` and no real guest page fault has reached it. The primary runtime's SIGSEGV/SIGBUS dispatch seam passes only with a synthetic callback. | Install the tested candidate memory adapter in an isolated app build, then exercise protect/read/write, guest CPU-write invalidation, unmap/remap, and a real fault through one handler before routing guest GPU submissions. |
| Critical | The imported symbol resolver does not match the runtime's static HLE shim ABI. | The app maps imports to `shim_sceGnmSubmitCommandBuffers(GuestContext*)` in `guest_modules.c`; that wrapper decodes guest registers and calls the current Metal implementation (`runtime/modules/libSceGnmDriver/ps4_gnmdriver.c:2186-2193`, `899-900`). The imported `gow3gpu_resolve(const char *scoped_nid)` returns PS4_SYSV ABI library functions, and the primary runtime has no caller of this resolver. The candidate-specific `a0a7a9d` adapter tests submit arguments and command-buffer lifetime but is not installed in that import registry. | Integrate explicit per-import adapters, beginning with submit and submit-done, then test real guest traffic and completion before switching the production owner. Never cast the returned function pointer to a `GuestContext*` shim. |
| Medium | MoltenVK is not a compatible fallback for the pinned renderer. | The probe at `/Users/ihabfawaqa/Library/Application Support/GOW3Lab/runs/vulkan_20261023_moltenvk_m2/vulkan_moltenvk.json` shows `robustBufferAccess2=false` and `nullDescriptor=false`; strict device creation fails with `VK_ERROR_FEATURE_NOT_PRESENT`. KosmicKrisp passes the tested required-feature/workload gate, so this is a fallback limitation rather than a current integration blocker. | Keep MoltenVK as a comparison result. Revisit if KosmicKrisp fails representative guest workloads; any workaround must preserve null-resource and bounds semantics. |
| High | Candidate memory and host-service callbacks are not installed by the production app. | Candidate commit `36e89bf` adds versioned guest-memory and host-service APIs with synthetic tests. The standalone ARM64 dylib now resolves project `runtime_*` symbols internally; `nm -u` found no unresolved project callback imports. The primary app still has no loader/install call for either callback table, so live memory and host services remain disconnected. | Add an isolated app loader and install the tested callback tables before candidate initialization; verify mapped guest reads, writeback, invalidation, and handled page faults in a bounded real workload. |
| High | Candidate C ABI lacks safe lifecycle teardown. | Standalone `gow3gpu_init` now constructs the Cocoa presenter with KosmicKrisp, but the C ABI has no shutdown export and does not coordinate Presenter, kernel-service, dispatch-timer, and SDL destruction. The smoke process uses `_Exit` after confirming init; no guest submission or library unload is exercised. | Add ordered renderer/VideoOut/kernel/window shutdown and failure rollback, then test init/use/teardown on the source-compatible Vulkan device. |
| High | The diagnostic Metal GCN path cannot produce a correct post-splash frame. | In the earlier default run `run_20261023_182220_026693`, the transition trace retains submission 872 at presentation 900: a 3-index draw of VS/PS `0xfb649c00/0xfb649800`, viewport/scissor 1920×1080, no depth target, target `0xbcdf8000`.
