FLATTENED USER DATA (arm64)
---------------------------
port/flatten_userdata_arm64.cpp gives each ReadConst whose base is a user-data pair and whose
index is an immediate its own slot in flattened_ud_buf (slots 16 and up). The driver fills the
slots from guest memory before each draw (FillFlatBuffer in ps4_gcn_translate.cpp) and binds
the buffer as bytes. ReadConst with a dynamic index, or a nested base, is marked unresolved and
the program is rejected.

BUILD
-----
Probe (standalone, no app):
  bash gpu/shadps4-recompiler/port/probe/verify_probe.sh <gpu-captures-dir> <build-dir>
  Needs C++23 (clang++), Homebrew fmt, magic_enum, boost, spirv-cross, and Xcode's metal
  compiler.
App: build.ninja compiles the same sources at C++23 into build/gcn/libgcn_recompiler.a
  (rule compile_cpp23, shims first on the include path) and links it into ps4_app with
  runtime/modules/libSceGnmDriver/ps4_gcn_translate.cpp and -lfmt.

LIVE PATH (ps4_gnm_metal.mm, opt-in)
------------------------------------
GOW3_GCN=1 selects the translated path. Each draw first tries TryBindTranslatedDraw:
translate both stages, bind vertex inputs from their V#s, bind buffers and push constants
from the current descriptors, and create the pipeline from the translated MSL. Any failure
(translation rejected, unsupported vertex format, MSL or pipeline error) falls back to the
heuristic path for that draw. Textures are bound from their T#s; samplers use a default sampler.
The default is the heuristic path, as before. GOW3_GCN_DEBUG=1 also prints the vertex input
struct and the T# words of each rejected image to stderr.

Descriptor validity: the translator reads V# windows through GuestToHost. Each program records
those windows (1 KB at each address) and is reused only while the bytes still match.
Rejected programs are cached too, so a rejected shader is not retranslated every draw.

TILING (driver texture upload, not part of this recompiler)
-----------------------------------------------------------
runtime/modules/libSceGnmDriver/ps4_tiling.h untiles a texture's mip 0 before the Metal upload. The
address math follows shadPS4's tiler (src/video_core/host_shaders/tiling.comp at commit
b4e7ae776071ceb1dd35004577a8719481e1d258, GPL-2.0-or-later). It covers tile modes 13 (Thin1DThin),
14 (Thin2DThin), 10 (Display2DThin) and 0..4 (Depth2DThin64..1K). Other modes upload as stored.
Checks so far: SelfTest (addresses are distinct and inside the surface span) passes for each
covered mode and several sizes; a 4096x1024 RGBA8 surface (mode 13) and BC1 surfaces (mode 13,
up to 2048x1024) decode to clean images. Not checked: 2D thin and display with real content (the
2D surfaces dumped so far were all zero), the 256-byte pipe interleave, and anything about the
console beyond those images.
GOW3_DUMP_TEXTURES=<dir> writes the first detiled RGBA8 and BC1 textures as raw rows for inspection.

Logging: the log shim prints the first 16 occurrences of each message, then every 4096th.

KNOWN LIMITATIONS (arm64 port)
------------------------------
- Dynamic SRT reads (ReadConst with a non-immediate index, or a nested pointer) are rejected.
  Their draws use the heuristic path.
- ReadConstBuffer (s_buffer_load of a V#) sources are not flattened. A program whose sharp comes
  from one is rejected by the unresolved-sharp check.
- Direct memory access (buffer device address) is off.
- Profile is minimal. Optional GPU capability flags are off, so the translator logs
  "not supported by the GPU" warnings for float32 denorm and signed-zero modes.
- Decoded from the draw: SPI_PS_INPUT_ENA/ADDR, SPI_PS_IN_CONTROL, SPI_PS_INPUT_CNTL_0..31,
  SPI_SHADER_COL_FORMAT, SPI_SHADER_Z_FORMAT. The color buffer data and number formats are
  still fixed to R8G8B8A8 unorm (CB_COLOR formats not decoded).
- Multisampled (2D MSAA, T# type 14) and integer textures are rejected, so their draws use the
  heuristic path. Tiled surfaces are detiled on upload (see the TILING note under LIVE PATH);
  tile modes other than the ones that note lists are uploaded as stored.
- Sampler state (S#) is not decoded; translated draws use a default sampler.
- A draw with no pixel shader binds a null fragment function.
- The VS input class (float, uint, int) is read from the emitted MSL, so the Metal vertex
  format matches the shader. Functions and pipelines are cached by program id, and each
  retranslated variant gets a new id, so a variant never reuses a function compiled from older
  MSL. (The earlier int4 failures came from that stale cache.)
- Draws whose vertex stage reads zero user data produce empty vertex buffers. The big draw in
  the capture has this shape (VS user data is zero at that draw), so its geometry is not
  reliable yet.
- ps4_app's fallback in build_and_run.sh (no ninja) compiles gpu/*.cpp at C++17 and does not
  know the recompiler. Use ninja.
