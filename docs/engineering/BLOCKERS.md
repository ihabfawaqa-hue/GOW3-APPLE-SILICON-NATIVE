# Verified blockers

Updated: 2026-10-24. Evidence below separates capability failures from missing integration work.

| Severity | Blocker | Evidence | Next falsifiable action |
|---|---|---|---|
| Critical | The candidate Vulkan path cannot allocate the pinned sparse buffer cache on Apple M2. | KosmicKrisp and MoltenVK both report `sparseBinding=false` and `sparseResidencyBuffer=false`; pinned `BufferCache` unconditionally builds 1–4 GiB sparse BDA arenas and calls sparse binds. Live candidate run `run_20261024_054738_284387` reaches Vulkan buffer creation then asserts before any draw; all 211 captured frames are black. | Evaluate a per-resident-range BDA buffer design with explicit guest-memory read/write and alias semantics; do not allocate multi-gigabyte dense mirrors or claim a feature-bit bypass. Otherwise retain the current native Metal production default and classify Vulkan M3 blocked. |
| High | Candidate GPU page protection and write ownership are not proven on real guest pages. | The opt-in loader installs the guest-memory API and fault handler; candidate fetch-shader bytes were successfully copied from a live guest VA.
